# verbatims Dataset Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the published `verbatims` review dataset: one Prague Airbnb listing, real multilingual text, PII stripped, generated ratings, a planted cleanliness trend, hand labels, and full provenance. All of it rebuildable without API calls.

**Architecture:** One TypeScript module per pipeline step under `src/pipeline/`. Every non-deterministic or manual decision is saved as JSON in `decisions/` (committed). `npm run build` replays raw Inside Airbnb files plus `decisions/` into `data/` with no API calls. LLM steps (rate, detect-names) are separate commands that write to `decisions/`. A small local labelling page (Vite + tiny API middleware) writes owner labels into `labels/`.

**Tech Stack:** Node 24, TypeScript (ESM), vitest, `csv-parse`, `franc` (language detection), `zod`, `@anthropic-ai/sdk` (structured outputs via `client.messages.parse` + `zodOutputFormat`), Vite for the labelling page, `tsx` to run scripts.

**Spec:** `docs/superpowers/specs/2026-11-19-dataset-design.md`

## Global Constraints

- Source: `https://data.insideairbnb.com/czech-republic/prague/prague/2026-09-20/data/reviews.csv.gz` and `.../listings.csv.gz` (confirm the URL resolves when downloading; it was read from a page summary).
- Raw files live in `raw/` and are **git-ignored**. They contain personal data. `.env` and `cache/` are git-ignored too.
- Never write a reviewer name, reviewer ID, host name, or redacted name into any committed file, including `decisions/`. Redactions are stored as `{ id, start, length }` only.
- Published review IDs are `r0001`… in date order of the **original** dates, assigned once in `decisions/sample.json` and stable thereafter.
- Model for every LLM call: `claude-opus-5-5`, `output_config.effort: "low"`, structured output via `zodOutputFormat`. Don't send `thinking` (it can't be disabled on this model); `max_tokens` 1024. Concurrency 4. The key comes from the environment (`.env` via `node --env-file`). Estimated cost for about 500 reviews is a couple of dollars.
- README wording: "Names and reviewer IDs removed. The original reviews remain public on Airbnb and in Inside Airbnb's dataset." Never "anonymised".
- Licence credit: "Data from Inside Airbnb (insideairbnb.com), licensed under CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/). Modified: see LICENSE-DATA.md." Code licence: MIT.
- Sub-rating keys, exactly: `overall, cleanliness, accuracy, checkin, communication, location, value`. Integers 1–5.
- Languages the owner reads (no translation aid): ISO 639-3 `eng, ces, slk, ukr, rus`.
- Git has no identity configured on this machine. Commit with `GIT_AUTHOR_NAME="Lavrentii Prokopovych" GIT_AUTHOR_EMAIL="lavrentiy.mel@gmail.com"` and the same `GIT_COMMITTER_*` per command. End messages with the Co-Authored-By and Claude-Session trailers from the session.

## Review Focus

1. Inside Airbnb `comments` contain `<br/>`, `<br>` and HTML entities (`&amp;`, `&#39;`). Normalise to plain text with `\n` before anything indexes into the text (pinned in Task 1).
2. Automated non-reviews ("The host canceled this reservation … This is an automated posting.") and comments under 20 characters must be excluded from the sample (pinned in Task 3).
3. Redaction offsets on Cyrillic and Czech text (diacritics, combining marks) must round-trip exactly. Offsets are JS string indices into the **normalised** text (pinned in Task 4).
4. A re-dated review must never land after the scrape date (2026-09-20) or outside the sample's date span, and the export must be sorted by the new date (pinned in Task 7).
5. The validator must catch any leftover reviewer name or host name of the sampled listing, as a whole word, case-insensitive and Unicode-aware, even when redaction missed it (pinned in Task 8).

### Task 4: strip PII (fields + name redactions)

**Files:** Create `src/pipeline/redact.ts`, `src/llm.ts`, `src/cli/detect-names.ts`, `src/cli/redact.ts`, `tests/redact.test.ts`

**Interfaces:**
- Produces:
  - `type Redaction = { id: string; start: number; length: number }`
  - `findOccurrences(text: string, name: string): Array<{ start: number; length: number }>`: whole-word, case-insensitive, Unicode-aware (`\p{L}` boundaries, `u` flag).
  - `applyRedactions(text: string, rs: Redaction[]): string`: replaces each span with `[name]`, applied right to left; throws on overlapping spans.
  - `src/llm.ts`: `export const MODEL = 'claude-opus-5-5'`; `callStructured<T>(schema: z.ZodType<T>, system: string, user: string): Promise<T>` using `client.messages.parse({ model: MODEL, max_tokens: 1024, output_config: { effort: 'low', format: zodOutputFormat(schema) }, system, messages: [...] })`. Throws if `stop_reason === 'refusal'` or `parsed_output` is null. Retries are left to the SDK default.
  - `npm run detect-names`: for each sampled review, asks Claude for `{ names: string[] }`, the person names exactly as they appear in the text (hosts, guests, staff), then turns each name into spans via `findOccurrences`. Writes `decisions/redactions.json` as `Redaction[]`, and prints `id: <count> redactions` plus a list of names the model returned that matched nothing. **Prints names to the terminal only. Never writes them to a file.** The reviewer's own `reviewerName` and the listing's `hostName` are always searched too, without asking the model.
  - `npm run redact -- add <id> "<name>"` / `remove <id> <start>`: manual fixes to `decisions/redactions.json`.

### Task 7: re-date (planted trend)

**Files:** Create `src/pipeline/redate.ts`, `src/cli/redate.ts`, `tests/redate.test.ts`

**Interfaces:**
- Consumes: sample (with original dates), `decisions/complaints.json`.
- Produces:
  - `type Move = { id: string; from: string; to: string }`
  - `planRedate(items: { id: string; date: string }[], confirmed: string[], opts = { want: 15, scrapeDate: '2026-09-20' }): { targetMonth: string; moves: Move[]; groundTruth: string[] }`. Algorithm (pinned by the spec):
    - Candidate months are the full months inside the sample's date span, not after `scrapeDate`, with at least 1 review.
    - The target is the month with the fewest confirmed complaints; ties go to the latest.
    - `avgMonthly` = confirmed / months in span.
    - Moves are confirmed complaints outside the target month, earliest first, up to `want`. Each new date is spread over the month's days deterministically (`day = 1 + (i * 7) % daysInMonth`).
    - Reduce moves until the month's total ≤ 2 × the busiest real month's total.
    - Require complaints in the month ≥ 3 × `avgMonthly`, otherwise throw with an explanation.
    - `groundTruth` = every confirmed complaint dated in the target month after the moves.
  - Writes `decisions/redate.json` `{ targetMonth, moves, groundTruth, rules: { want, minRatio: 3, maxMonthFactor: 2 } }`.
